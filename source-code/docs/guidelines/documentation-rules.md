# Documentation Rules

## Principles

1. Documentation must live close to code
2. Code comments explain intent
3. Markdown explains context

## Structure

- Domain → XML comments
- Modules → Markdown
- Architecture → Markdown + diagrams

## Anti-patterns

- ❌ Document only in README
- ❌ Explain obvious code
- ❌ Duplicate documentation

## Rule for AI usage

When generating code:
- Always include XML documentation for domain
- Follow DDD commenting guidelines
